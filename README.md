# ロト数字選択スタジオ

ロト6・ロト7・ミニロト・ナンバーズ3・ナンバーズ4の出現頻度分析と候補生成。

https://yuryuki-ai.github.io/loto-studio/

ロト6とミニロトは次の3条件を使います。

1. ロト6は直前10回に一度も出なかった本数字を、ミニロトは直前5回に一度も出なかった本数字を、ちょうど3個含める。
2. 前回の本数字を、ロト6はちょうど1個、ミニロトはちょうど2個含める。
3. 前回の本数字を含む連続ペアを、全体でちょうど1組含める。別の連続ペアや3連続以上は除外する。

ロト6・ミニロトには合計・奇偶・大小による除外条件はありません。

ロト7の暫定5条件では、直前10回に一度も出なかった本数字を2〜4個、前回の本数字をちょうど2個、連続ペアをちょうど1組、奇数を2〜5個、1〜18を2〜5個含めます。連続ペアが前回数字を含むことは必須にしません。3連続は2組と数えるため、候補から外れます。合計値は参考表示のみで、判定には使いません。

ナンバーズは各桁の0〜9を別々に集計します。頻度3〜4回に該当する桁をちょうど3桁、前回と同じ位置・同じ数字を1〜2桁含めます。隣接桁の差が1のペアを全体でちょうど1組含め、その片方は前回と同じ位置・同じ数字です。先頭の0と重複数字を許可し、9と0は連続扱いしません。全1,000/10,000通りから条件一致候補を列挙し、ストレート向け候補として表示します。

公平な抽せんでは各番号・組み合わせの確率は同じです。このルールで当選確率が上がる根拠はありません。

取得元：https://kujishirube.info/ 。各種類の最新24回を収集し、回号の連続性・日付・数字の範囲・先頭の0・既知の結果との一致を検証して公開します。

平日21:30・23:30（日本時間）にGitHub Actionsで収集・Pages再公開を試行します。GitHub側の遅延や取得元の反映遅れにより時刻どおりに更新されない場合があります。Actionsから手動実行も可能です。

アプリ起動時はhistory.jsonをキャッシュを避けて再確認し、基準に使用した回号・日付・前回数字を表示します。前回抽せん予定日より古い場合や取得失敗時は注意文を表示します。年末年始の抽せん休止は概算のため、表示回号・日付と公式結果も確認してください。公開データの再確認ボタンは、公開済みのデータを読み直す機能です。

ブラウザによる過去の入力欄復元で種類が食い違わないよう、pageshow時に選択中の種類のデータを読み直します。手入力データは利用者のブラウザに保存します。

## 過去の当せん番号での検証

直近200回を取得し、各回の直前の結果から条件を判定します。頻度の集計はロト6・ロト7で10回、ミニロトで5回、ナンバーズで24回です。先頭の最大176回が対象です。5種類に対応し、対象回数を選べます。前回一致数はロトでは固定し、ナンバーズでは1〜2、1、2を選べます。全条件一致の回だけを表示するほか、不一致理由・分析対象回の範囲・全判定のCSVを確認できます。

全条件一致は、当せん番号がルール上の候補に含まれることを意味します。抽せん前にランダム生成で実際に表示された記録でも、購入や的中の実績でもありません。条件一致率を将来の的中率として扱わないでください。ナンバーズはストレートの桁順を判定し、ボックスや下位当せんは判定しません。バックテストは手入力欄とは独立した公開履歴を使用します。

バックテスト用のbacktest-history.jsonも平日夜の更新で再収集します。履歴の回号が欠落・重複している場合は検証を中止します。
